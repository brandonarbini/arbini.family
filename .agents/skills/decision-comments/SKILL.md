## Comment the decision, not the mechanism

The code says what it does. A comment is worth its space only when it carries something the code
cannot: why this, and what happens if someone changes it.

The test for a comment is whether a competent reader who has not seen the failure would otherwise
undo the line. If they would, it needs a comment. If the line is self-evident, deleting the comment
improves the file.

**Name the rejected alternative.** "We use X" ages into noise; "X rather than Y, because Y did Z"
survives, because the next person's instinct _is_ Y, and now they know how that ends. Most of the
value is in the second clause.

**Put it at the decision site.** A note in a README about a line in a config is a note nobody reads
before editing the config. Rationale that lives where the edit happens is the only rationale that
gets read at the moment it matters.

**Record the symptom, not just the cause** — the error string, the environment it appears in, the
fact that it only fails in production. Someone will arrive at the comment by searching for that
symptom, and that is the search that has to hit.

## Say what is load-bearing

An invariant that nothing declares is an invariant someone will relax to make a test pass. State it
plainly, in the module that enforces it, and say what breaks: "N things are load-bearing" followed
by what and why is worth more than the same content spread across the file as asides.

A rule that is genuinely non-negotiable can say so in capitals. Used once per module it reads as
emphasis; used everywhere it reads as noise and stops working.

## Single-source an authority document

When a specification, schema or format has an authoritative document, do not paraphrase it. A précis
beside a specification is a second authority, free to drift — and the drift is invisible, because
both documents look fine in isolation and only the behaviour disagrees.

When something needs a shorter version — a prompt, an onboarding guide, a quick reference —
**select** rather than rewrite: quote the authority verbatim and omit what is irrelevant. Then lock
the selection with a test, so renaming a section in the source fails loudly instead of silently
producing a truncated copy.

Where a document is a copy of an external source, mark it as a copy and say it is never edited —
including for typos. A "small fix" to a vendored authority is how the copy stops being one.

## READMEs and commits

A subsystem README explains the shape and the reasoning — what the pieces are, which decisions are
load-bearing, what will surprise you. It does not enumerate the files; the directory already does
that, and the list is wrong within a month.

A commit message says why the change was made and what would otherwise go wrong. The diff already
says what changed.
